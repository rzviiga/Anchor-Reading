# AnchorRead

**让视线有处落脚。**

为 Mac 屏幕上的英文添加词首强调。AnchorRead 在本机通过 OCR 寻找可见的英文单词，再用透明覆盖层绘制原生粗体词首。按下 **⌃⌥⌘B**，即可在当前阅读的应用中开启或暂停。

[English](README.md) · [MIT 许可证](LICENSE)

| 原文 | 词首强调 |
| --- | --- |
| Find your place in every word. | **Fi**nd **yo**ur **pl**ace **i**n **ev**ery **wo**rd. |

*上表仅演示默认 40% 设置的格式，不是实际截图或 OCR 准确率展示。*

## 为什么做 AnchorRead？

阅读发生在浏览器、PDF 阅读器、邮件客户端和各种桌面应用中。AnchorRead 通过覆盖层给可见内容添加词首强调，无需修改文档、替换系统字体或安装浏览器扩展。

它面向喜欢用单词开头作为视觉提示的英语读者。实际覆盖范围取决于文字是否可识别、字形是否能可靠匹配。

## 功能

- **快捷键开关**：使用 Control + Option + Command + B，或通过菜单栏控制。
- **可选节能模式**：操作结束后截图识别一次，静止时保留强调，不维持捕获流或周期 OCR。默认关闭，并记住选择。
- **节能模式键盘感知**：输入、删除、换行、导航和快捷键操作时隐藏旧强调，停止输入后更新；需要 macOS 输入监控权限。
- **候选窗避让**：节能模式降低覆盖层层级，并跳过与其他应用浮动窗口重叠的强调，覆盖标准输入法候选窗、菜单等场景。
- **跨应用、多显示器**：识别捕获画面中的可见英文；PDF 和图片中的文字足够清晰时也可处理。
- **原生粗体词首**：通过 CoreText 匹配原单词字形，绘制粗体前缀，保留原词尾像素。
- **可调强调范围**：仅首字母、词首 40%、词首 50%；百分比模式最多强调四个字母。
- **滚动时隐藏**：滚动期间让出画面，停稳后恢复强调。
- **选区保护**：按住鼠标时隐藏；选字手势结束后继续隐藏，保留原应用的选区显示。
- **本机处理**：使用 Apple Vision 和 ScreenCaptureKit，无需账号、云端 OCR 或第三方运行时依赖。

## 当前状态与要求

AnchorRead 目前是 **macOS 早期原型**，版本为 **0.6.0**。应用包和源码模块暂时沿用原名 **Anchor Overlay**。

- macOS 14 或以上。
- 当前准备的构建面向 Apple Silicon，尚未验证 Intel 兼容性。
- 需要 macOS 屏幕录制权限，以读取可见画面。
- 节能模式的跨应用键盘感知还需要 macOS 输入监控权限。未授权时，鼠标触发更新和手动刷新仍可使用。
- 当前菜单界面为简体中文。

0.6.0 已完成编译和本地签名，尚未实测本版键盘、输入法行为和节电幅度，没有准确率或延迟保证。不同桌面应用中的选区保护行为也仍需验证。

## 构建与运行

准备 Python 3，以及包含 Swift 6 工具链和 macOS SDK 的 Xcode Command Line Tools。在仓库根目录执行：

```sh
python3 scripts/build.py
```

脚本编译应用和开发辅助程序，并进行本地临时签名；**不会运行测试**。应用输出位置为：

```text
dist/Anchor Overlay.app
```

1. 退出旧版 Anchor Overlay。
2. 打开构建出的应用，菜单栏会出现图标。
3. 使用 **⌃⌥⌘B** 或菜单开关开启强调。
4. 按提示前往「系统设置 → 隐私与安全性 → 屏幕录制」授权。不同 macOS 版本的设置名称可能不同；授权后可能需要重启应用。

本地构建采用 ad-hoc 签名，尚未进行 Developer ID 公证。

生成包含应用、源码与说明的压缩包：

```sh
python3 scripts/package.py
```

当前输出为 `dist/Anchor-Overlay-0.6.0.zip`。仓库也提供 `Package.swift`，供兼容的 Swift/Xcode 环境开发使用；上述脚本负责生成可运行的应用包。

## 使用方式

| 控制项 | 行为 |
| --- | --- |
| **⌃⌥⌘B** | 开启或暂停强调。 |
| **节能模式（按需截图）** | 在按需截图与现有持续捕获之间切换。默认关闭，重启后保留选择。 |
| **键盘感知** | 显示监听状态，申请输入监控权限或重试连接；仅在节能模式下显示。 |
| **刷新当前画面** | 节能模式下手动请求一次截图，也会结束选区保护。 |
| **强调范围** | 仅首字母、40%（默认）、50%；百分比模式最多四个字母。 |
| **识别分辨率** | 1×、1.5×、2×（默认）；捕获宽度上限为 2,880 像素，保留已有设置。 |
| **恢复阅读增强** | 结束选区保护，恢复强调。 |
| 状态信息 | 显示进入字形匹配的识别词数、增强成功词数，以及 OCR、字形处理耗时。 |

例如，`watermark` 在 40% 模式下显示为 **wate**rmark，在仅首字母模式下显示为 **w**atermark。

### 节能模式

在菜单栏点击 **节能模式（按需截图）**，出现勾选表示已开启。强调运行中切换，会先结束当前捕获和 OCR 工作，再启动选定模式；强调暂停时切换，只保存设置，供下次开启使用。

| | 常规模式 | 节能模式 |
| --- | --- | --- |
| 捕获方式 | 持续 ScreenCaptureKit 捕获流，检查画面变化。 | 支持的交互结束后，每个显示器截图一次。 |
| 更新时机 | 开启期间根据捕获到的变化刷新。 | 首次开启、普通点击或滚动结束、已授权的键盘操作、切换应用或桌面空间，以及手动刷新。 |
| 静止阅读 | 捕获流和调度继续运行。 | 保留上次强调，不运行捕获流、重复像素检查、定时刷新或 OCR。 |
| 增强效果 | 现有 OCR 和原生粗体词首。 | 沿用相同 OCR、强调范围、分辨率与渲染方式。 |

节能模式在**鼠标操作结束约 0.3 秒后**截图。键盘操作额外等待 **0.5 秒无新输入**，因此松键且停止输入约 **0.8 秒后**截图，截图及 OCR 耗时另计。按住鼠标或按键、选区保护期间，以及本应用菜单打开时，暂停启动新截图。多显示器依次处理；后续交互会使旧结果失效。整轮处理结束后，状态栏显示 **节能 · 静止休眠**。

此模式适合以静态内容为主的阅读。休眠时不持续检查强调区域背后的像素，网页自动刷新和延迟加载可能让旧强调暂时覆盖在已变化的内容上。未获得输入监控权限，或 macOS 安全输入阻止事件传递时，键盘操作也可能无法触发更新。此时使用 **刷新当前画面**；动态内容较多时，可关闭节能模式。单次截图仍需要屏幕录制权限。

“休眠”指捕获和 OCR 流程停止工作，不代表系统睡眠或零耗电；已有覆盖层窗口和输入监听仍然可用。实际节电幅度及温度变化尚未测量。

### 键盘输入与输入法候选框

开启节能模式后，在菜单选择 **键盘感知：需要输入监控权限…**，到「系统设置 → 隐私与安全性 → 输入监控」允许 Anchor Overlay，必要时重启应用。监听实际连接成功后，菜单才显示 **键盘感知：已开启**；不会只凭授权状态就显示已工作。

键盘监听仅在节能强调运行期间安装，观察按下、松开和修饰键变化，不提取输入字符串，不修改输入。暂停强调或切回常规模式后移除监听。连续输入通过可取消的单次延迟合并，不增加周期键盘轮询。

输入时立即隐藏旧强调，并使待处理截图结果失效。停止输入后，截图前和显示结果前分别检查其他应用浮动窗口的位置，跳过与这些区域重叠的强调；覆盖层从状态栏以上降到普通浮动层级。这样可以避开标准候选窗，无需猜测某个输入法的进程名。若无法取得窗口位置，该轮不显示强调。

此机制依据窗口位置保护，不是通用的跨应用组词状态检测。直接画在应用普通窗口内的自定义候选框、安全输入和延迟弹窗仍需实机验证。候选窗内容本身不专门增强，其他浮动面板中的文字也可能被跳过。

### 选择和复制文字

覆盖层窗口设置为鼠标穿透，不获取键盘焦点。按住鼠标期间，应用隐藏强调并暂停启动新的 OCR。

拖选、双击/三击、Shift 单击后，选区保护会继续隐藏强调。此时在原应用中正常复制即可。下一次普通单击、滚动、切换应用，或点击菜单「恢复阅读增强」，都会结束保护。

保护逻辑依据输入手势判断，不读取其他应用的实际选区。因此，拖动窗口、滑块也可能触发保护。节能模式授权键盘感知后，**Command+A**、**Shift+导航键**也会进入保护，**Command+C**保持保护；应用自定义的其他键盘选区操作可能无法识别。

## 工作原理

```text
屏幕上的可见内容
        ↓
ScreenCaptureKit：持续捕获或单次截图，排除本应用
        ↓
Vision：识别英文与完整单词框
        ↓
CoreText：匹配原字形，计算词首位置
        ↓
透明覆盖层：原生粗体词首 + 原词尾像素
```

后台仅运行一个 OCR 工作线程。常规模式在检测到画面变化或用户交互后丢弃过期结果；局部变化时，可保留未变化的强调。节能模式改为由交互触发可取消的单次延迟任务，静止时不比较屏幕像素。两种模式都使用有大小限制的字形匹配缓存。

原字形匹配失败后，会尝试更多已安装字体，并对两个最接近的候选进行小范围位置和尺寸微调。单词仍需通过原画面像素校验，才会绘制强调。

## 隐私

屏幕录制权限用于获取 OCR 所需的画面。画面与识别文字在本机内存中处理；常规模式运行捕获流，节能模式按需获取单张截图，处理后释放其像素。应用不将截图或识别文字保存到磁盘，不捕获音频，不上传屏幕内容。暂停强调会停止捕获，并等待已开始的工作结束。

输入监听仅用于决定何时隐藏或恢复覆盖层，不替换、不重放输入事件。键盘监听只使用事件类型、物理按键编号和修饰键状态，临时保留按住的键；不提取输入字符串，不记录键盘历史，不上传键盘活动。候选窗检查仅使用窗口位置和层级，不记录标题或文字。

## 已知限制

- **只处理可见英文。** 不修改 PDF、网页、原始文档或导出文件；被遮挡、屏幕外或受捕获保护的内容无法增强。
- **可能漏词。** 小字号、特殊或不可用的字体、低对比度、复杂背景和倾斜文字可能导致匹配失败。
- **字形匹配是近似结果。** 较高的匹配分数不能保证字体和词首位置完全正确。
- **恢复需要时间。** 密集页面和难匹配的字体可能延长滚动后的等待；持续动画可能推迟新结果。
- **菜单耗时不是全链路延迟。** 它只报告 OCR 和字形处理时间，不包含从画面变化到强调显示的全部过程。

## 参与贡献

欢迎提交 Issue 和 Pull Request，尤其是漏词、词首位置不正确、文字选择异常和滚动后恢复缓慢等问题。

报告问题时，请提供 macOS 版本、目标应用、显示缩放、识别分辨率、强调范围和简短复现步骤。识别问题最好附带不含敏感信息的示例句子，以及已知的字体名称。

尽量将渲染、识别和交互修改分别提交，并写明实际完成了哪些验证。修复识别或调度问题时，欢迎补充对应回归覆盖。
