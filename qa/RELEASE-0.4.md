# Anchor Overlay 0.4.0

针对开启覆盖层后选中文字受影响的问题，增加持续的鼠标操作暂停和选区保护。OCR、字体匹配与原生粗体输出未修改。

## 代码发现与边界

旧窗口已有 `ignoresMouseEvents = true`、非激活面板、禁止成为 key/main 窗口和空 hitTest。旧监听也没有吞掉本地事件。因此，不能仅凭代码断言“窗口拦截了鼠标”。

明确发现的缺口是：旧版本只在每次点击/拖动后隐藏约 160 ms，没有记录按下至松开的全过程。拖选中停顿就可能允许不透明文字补丁重新出现。该缺口可能遮住或干扰选区的视觉反馈；是否解释用户的全部现象未实机确认。

## 修改

- 监听鼠标按下、拖动与松开，操作期间同步隐藏所有面板；主线程显示回调和后台 OCR 调度同时受暂停状态约束，丢弃在暂停期间完成的旧结果。
- 松开普通点击后重新等待画面稳定；拖选、双击/三击及 Shift 单击后保持隐藏，直到下一次普通单击、滚动或应用切换，也可用菜单手动恢复。
- 仅在按住鼠标期间使用 50 ms 按钮状态复查，补偿其他应用模态跟踪期间可能漏报的松开。它不捕获画面，也不监听键盘内容。
- 继续只观察全局鼠标事件，并原样返回本地事件，不注入、不重放输入；没有新增权限请求。
- 鼠标动作只是选区的近似判断。移动窗口、拖动滑块也可能进入保护；纯键盘选择没有专门检测。右键不会主动清除已进入的选区保护。

事件监听行为参考：[Apple — Monitoring Events](https://developer.apple.com/library/archive/documentation/Cocoa/Conceptual/EventOverview/MonitoringEvents/MonitoringEvents.html)。

## 验证

按用户此前要求，仅编译、签名、打包；不运行测试、应用或屏幕 OCR。没有实测选择、复制、拖动与恢复行为，也没有性能数据。
