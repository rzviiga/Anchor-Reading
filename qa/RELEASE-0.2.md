# Anchor Overlay 0.2.0

针对用户反馈的三个问题修改，最终版本已编译打包。按照用户要求停止追加测试，不声明最终版本通过回归、性能或实机验证。目录内其他测试报告属于旧版或中间版本，不代表本版本。

## 刷新时强调消失

旧版在约 1.2 秒的复查周期调用 `changed` 和 `invalidate`，主动清空整个覆盖层，等 OCR 重新完成后才显示。

新版将复查改为 `requestRefresh`，不改变画面版本、不重置停稳时间、不清空已显示内容；结果准备好后原位更新。另对每个已显示单词的实际屏幕像素与原始参考帧进行比较，局部变化仅移除受影响的单词，保留其余强调。滚动、拖动、缩放、暂停时仍按约定立即隐藏。

## 光晕式加粗

生产路径不再调用旧的 `StrokeMask` 半透明膨胀描边。改用 CoreText：用单词的真实像素匹配候选字体，在局部纯色背景上绘制该字体的真实粗体词首。词尾复制原始像素，不从 OCR 文本重新生成。词首按原来的水平宽度排版。

匹配的颜色与截屏像素使用相同色彩空间，避免深色背景上的色块。默认分辨率改为 2×，已有手动选择的设置仍保留。无法充分匹配的字体或复杂背景会跳过，不再退回光晕描边。

这是候选字体匹配，不能保证还原每个网站的原始字体。候选包含系统字体、Helvetica、Arial、Georgia、Times、Menlo 等常见字体。

## 词首坐标错误

最终版本改用 Vision `accurate` 识别完整单词，并验证整个单词的像素形状。词首的起点与终点来自匹配后 CoreText 的字形排版，不再使用 Vision 的局部字符框。

对于 `Remove the dreamnia watermark in downloads.`，40% 设置的目标是强调 `wate`；仅首字母设置的目标是 `w`。已加入相关回归源码，但最后一次算法修改后按用户要求没有继续运行它，不能称为已验证全部场景正确。

## 性能范围

字形匹配结果按文字、词首长度和实际像素缓存，缓存最多 1024 项。仍只允许一个 OCR 工作线程，丢弃过期结果。

`accurate` OCR 和原生字形匹配可能增加第一次识别或滚动停止后的恢复时间。本版本没有可引用的最终性能数据；旧版约 71 ms 的数字不适用于此版本。

## 更新方式

退出旧版，解压新版，打开新的 `Anchor Overlay.app`；快捷键仍为 ⌃⌥⌘B。实机体验由用户自行测试。
